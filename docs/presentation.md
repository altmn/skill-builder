# Repository presentation

The main page helps a person understand the result, choose Create/Audit/Explain, and begin in the right environment. Keep helper mechanics, packaging internals, all-rule routing, knowledge-base hashes, and historical trials in linked technical/evidence documents. Preserve the records and current qualifications rather than turning every detail into introductory copy.

Use the same task labels as the sibling repositories where applicable: Try it, Get started, Get help, Update or remove, Where it works, Technical details, Contribute. Keep Skill Builder's light/dark identity, task chooser, workflow illustration, and examples distinct. Use real headings, meaningful links, and selectable text; essential information should not depend on image color or a wide diagram.

Offer AI-assisted setup, use, troubleshooting, and maintenance beside direct instructions. Label where each prompt belongs. ChatGPT uses actual `@` selection; Codex uses `$` or its picker. Browser prompts guide setup and planning; the current package's `requires_local_executor: true` remains intact and its full workflow is desktop-only. Do not imply public directory approval or a universal ZIP importer.

Download counters may be shown **only if the displayed metric is verifiably at least 100**. No counter is included because no qualifying metric is established here. Before adding one, record the metric source, meaning, date/window, and count, and keep the display conditional or remove it if the value falls below 100. Downloads, installations, and source archive requests are different metrics.

## GitHub settings when publishing

Suggested About description: “Turn a repeatable task into an AI skill, or review and improve one you already use.” Suggested accurate topics: `agent-skills`, `skill-development`, `codex`, `ai-agents`, `developer-tools`. Use the repository as the homepage until a useful separate documentation site exists.

Use original/shareable examples and the existing icons. A future social card should remain readable when small, use a 1280×640 canvas, and stay below 1 MB. Changing repository settings and publishing a directory listing are separate from source preparation.

## Maintenance and references

Presentation-only changes still require separate reasoned Create/Audit impact decisions. Evaluate effects on instructions, helper outputs/templates, shared resources, target-specific evaluation, host adapters, and packaging before editing and before delivery. A changed example does not establish a downstream behavior gain.
