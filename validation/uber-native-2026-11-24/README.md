# Native create/audit comparisons — 2026-11-24

**A small audit advantage was observed; no creation-quality advantage was
demonstrated.** This panel ran all four field tasks on other skills with clean
no-target-skill and pre-improvement controls. It compares the unchanged improved
payload with master `afcad44`, not the older explanation-only pilot.

## Native creation

Each condition created a notes extractor and an evaluation-receipt reviewer.
Independent reviewers, given neutral artifact bundles and a frozen rubric,
passed all four original artifact checks for each of the six delivered skills.
File count, verbosity, helper/template choice and builder-specific formats earned
no credit. Creation therefore tied: **2/2 tasks in every condition**.

Two fresh read-only behavior probes were scheduled for each generated skill:
adversarial/literal/null extraction plus missing notes, or unknown activation/
cost/attempt accounting plus malformed `rule_id` handling. **All 11 completed
probes passed** their 40 checks. One improved-version receipt-reviewer probe hit
selected-model capacity before any skill read/tool call, then its 120-second
deadline. Its empty answer and five unknown checks remain retained, with no
retry. That attempt establishes neither successful behavior nor a skill defect.

## Native audit

Each condition audited the incident-queue and deliberately flawed receipt-review
subjects. Every condition found the substantive planted defects: hostile setup,
unsupported support/savings, undefined task decisions, keyword grading, wrong
fields, inferred activation and suppressed failures. The difference was source
localization under the frozen requirement that every material citation be correct.

| All original task checks and observed invariants | No target skill | Previous `afcad44` | Improved |
| --- | ---: | ---: | ---: |
| Creation tasks | 2/2 | 2/2 | 2/2 |
| Audit tasks | 1/2 | 1/2 | 2/2 |
| Individual task assertions | 17/18 | 17/18 | 18/18 |
| Generated-subject probes | 4 passed | 4 passed | 3 passed, 1 infrastructure-blocked |

The unassisted incident audit anchored the version and write operation to the
wrong lines. The previous-version receipt audit anchored the keyword gate and
canonical example to unrelated lines. Their substantive findings retained
credit; `source_locations` failed. The improved audits met that criterion on
both tasks. [Independent grades](grading/main-semantic.json),
[probe grades](grading/probe-semantic.json), [summary](summary.json).

## Controls, identity and effects

The [protocol](protocol.json), [probe cases](probe-protocol.json) and
[grading/calibration plan](grading-plan.json) were frozen before the relevant
execution/grading. Twelve main CLI calls and twelve probe calls used fresh,
unrelated projects, one attempt per case/condition, matched settings and a fixed
randomized condition order, with at most two calls concurrent. The CLI was
0.170.0. Exact resolved model version and dollar costs were unavailable.

Controls had no target skill copy or repository ancestry/instructions. Known
user roots contained no skill-builder entry; supported prompt inventories and
actual command streams were independently checked. No baseline read builder
resources. All eight assisted main runs exposed full entrypoint reads tied to
the actual copied payload; all eleven completed probes exposed full subject
reads. Input/target bytes stayed unchanged. Complete observed command streams
show no target setup execution, extra model/agent call, network, install or
publication action. Creation writes stayed under the authorized output tree.
See [control inventory](control-inventory.json) and [observations](observations.json).

The runner put audit files under `./target` identically across conditions rather
than retaining their original package-folder names. That can introduce a real
directory/name mismatch; the graders gave no extra primary credit for it. Source
file bytes and the original task criteria were unchanged. This adapter deviation
limits extrapolation to an exactly packaged installation.

## Resource observations and interpretation

| Main task totals | No target skill | Previous | Improved |
| --- | ---: | ---: | ---: |
| Reported input tokens | 445,831 | 1,730,659 | 1,596,050 |
| Of those, cached input tokens | 334,592 | 1,471,488 | 1,344,128 |
| Reported output tokens | 6,166 | 17,009 | 15,472 |
| Shell/tool command calls | 14 | 36 | 33 |

These are cumulative provider-reported turn inputs, including repeated/cached
context, not unique activated-text measurements. The improved condition used
about 7.8% fewer main input tokens than the previous version in this panel, but
about 3.6 times the unassisted baseline. Provider caching, concurrent execution,
unexposed model version and one trial per task prevent causal speed or dollar
savings claims. The blocked probe has unknown usage, not zero; probe resources
are kept separately and all attempts remain in the observations.

No main subject invoked the new `review.py`/`ablate.py` companions or directly
read the Uber supplement. The results assess the improved payload's observed
workflow behavior, not native uptake or benefit of every new mechanism. Some
creation KB reading was partial; these bounded outcomes do not certify completion
of the full 99-rule workflow. All three notes checkers use constrained wording
and still need independent semantic review.

The result supports a **narrow observed citation-accuracy improvement**, with
creation and completed behavior probes tied. Four public historical-adaptation
tasks, one trial per condition and LLM semantic grading do not establish general
reliability or that the differences will repeat. No runtime instructions were
changed to improve these scores, and no failure was rerun away.
